# Резервные копии и обновления

## Резервные копии
Копия — это ZIP-архив с **базой данных** и **загруженными файлами** (фотографии сотрудников, отсканированные документы,
логотипы, печать).
- Делается **автоматически каждый день** после выбранного часа, **перед каждым обновлением** и перед миграциями базы.
- **Сделать копию сейчас** — перед важной операцией (большой импорт, закрытие месяца).
- Хранятся последние *N* автоматических копий (настройка «хранить последние»); ручные копии сами не удаляются.
- Периодически **скачивайте** копии и храните их ещё где-нибудь (другой компьютер, внешний диск, облако): если выйдет из
  строя диск сервера, копии на нём пропадут вместе с ним.

Как сохраняется база:
- **SQLite** — точная копия файла базы;
- **PostgreSQL** — `pg_dump` (если программа PostgreSQL установлена на сервере);
- **другая база** (MS SQL, MySQL, Oracle) — универсальный экспорт данных, который можно загрузить в новую базу любого типа.

**Восстановление** выполняет администратор сервера: SQLite — файл базы заменяется файлом из архива;
PostgreSQL — `pg_restore`; универсальный экспорт — в новую базу, `manage.py migrate`, затем `manage.py loaddata data.json.gz`;
папка `media` из архива копируется в `instance/media`. Если не уверены, обратитесь к поставщику.

## Обновления
Новые версии приходят от поставщика как **подписанный пакет** (`crm-update-<версия>.zip`):
1. **Загрузить пакет обновления** — система проверяет подпись и версию. Изменённый файл, файл другого происхождения
   или более старая версия не принимаются.
2. **Установить и перезапустить** — делается резервная копия, сервер останавливается, заменяет файлы программы,
   устанавливает новые библиотеки (если нужно), обновляет базу и запускается снова. Обычно это занимает 1–3 минуты;
   страница обновится сама.
3. Если что-то пошло не так, система **сама возвращается** к предыдущей версии (старые файлы хранятся в
   `instance/updates/rollback/`).

Если поставщик дал вам **адрес обновлений**, впишите его здесь: **Проверить новую версию** показывает, есть ли она, а
**Скачать** готовит её к установке.

Если система работает в Docker, она обновляется новым образом (`docker compose pull && docker compose up -d`).

Данные предприятия (база, конфигурация, загруженные файлы) при обновлении не затрагиваются.
