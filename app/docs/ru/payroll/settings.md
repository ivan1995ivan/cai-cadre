# Настройки зарплаты (константы 2026)

Для того, кто настраивает зарплату: *Администрирование → Настройки → Константы зарплаты* и *Виды расчёта*. У каждой константы
есть **«действует с»**: при изменении закона добавляется новая строка со своей датой, старая остаётся для прошлых месяцев.
Основание, ещё не подтверждённое официальным текстом, помечено **«проверить»** — значение исправляется здесь, без
программиста.

**Новые виды расчёта** (автоматические): **MINIM** «Доплата до минимальной зарплаты», **BOALAACC** «Пособие при несчастном
случае на производстве (дни работодателя)», **CASMIN** «НКСС на разницу до минимальной базы». Автоматический вид можно сделать
неактивным (например MINIM), но закон требует минимальную зарплату — предупреждение остаётся.

**При обновлении старой установки** миграция исправляет только то, что осталось с поставленным значением: минимальная
зарплата 5 500 → 6 300, средняя 17 200 → 17 400, старые основания; единая надбавка за сверхурочные становится оплатой первых
часов (100 + надбавка). Заявления на освобождения «на год» становятся заявлениями со сроком с / до, иждивенцы — строками;
заявления с «S» (отменено) помечаются «Проверить».

**Транспорт (S6b)** — для настраивающего: автоматические виды **KM** (оплата за км — входит в поставляемую базу профсоюза /
алиментов и в доплату до минимальной зарплаты), **DIURNA** (не облагается, без CAS / CNAM), **DIURNAEX** (сверх норм, облагается);
константы `per_diem_pct` 100, `per_diem_private_min_pct` 70, `per_diem_short_pct` 20, `per_diem_day_pct` 40,
`per_diem_meals_pct` 20, `per_diem_domestic_pay` 0; см. *Транспорт*.

**Время без производства, надбавка за вредность, талоны на питание (S5b)** — для настраивающего:
- новые автоматические виды расчёта: **STATIONARE** (простой), **SOMAJT** (технический простой), **GARANT** (гарантия сдельщика),
  **VATAM** (надбавка за вредность из подразделения / должности), **TICHET** (облагаемая часть талонов) и удержание **TICHETN**;
  STATIONARE, SOMAJT, GARANT, VATAM входят в базу профсоюза / алиментов (поставляемую);
- новые константы: `idle_employer_pct` 100, `idle_nofault_pct` 66,6667, `idle_worker_pct` 0, `tech_unemployment_pct` 50,
  `shortfall_nofault_pct` 66,6667, `meal_voucher_value` 0 (укажите номинал талона), `meal_voucher_min` 35, `meal_voucher_cap` 70,
  `meal_voucher_night_pct` 50;
- оклад принятого / уволенного в месяце платится от нормы всего месяца (до сих пор — полный оклад);
- см. *Фабрика: время без производства, надбавка за вредность, суммированный учёт* и *Талоны на питание*.

**Сдельная оплата (S5a)** — для настраивающего:
- новые виды расчёта **ACORD** («Сдельная оплата»: работы из утверждённых отчётов о выработке) и **ACORDP** («Прогрессивная
  сдельщина»: надбавка сверх нормы по работам с отметкой «прогрессивная») — автоматические, облагаемые, с CAS и CNAM, входят
  в средний заработок и в базу поставляемых профсоюза / алиментов;
- **ступени ACORDP не поставляются**: в виде ACORDP поле «Ступени прогрессивной сдельщины» — «от % выполнения : надбавка %»,
  например `100:50, 110:100`, из коллективного договора; без ступеней ACORDP не начисляется;
- новый способ оплаты **«Сдельно»** (трудовое отношение, приказ), часовой тариф разряда обязателен;
- в формулах: `OreNormate`, `OreAcord`, `IndeplinireNorma`; см. *Производство: сдельная оплата*.

**Виды часов и оплата по должности (S4b)** — для настраивающего:
- новый вид расчёта **ORE** («Часы по видам», автоматический: оплачиваемые часы × тариф, с гарантированными часами) — входит
  в средний заработок для отпуска / больничного и в базу поставляемых профсоюза / алиментов; у вида часов может быть свой вид
  расчёта (автоматический, «Часы по видам»), привязанный в *Настройки → Виды часов*;
- **CUMUL** называется «Доплата за совмещение / замещение» и считается по записям совмещения в отношении (ТК ст. 156), а не
  по совместительству; «Доплата за совмещение (%)» в отношении сама перенесена в записи, суммы те же;
- в формулах: `Ore.COD`, `OrePlatite.COD`, `Garantat.COD`, `Tarif.COD` (см. *Виды часов, тарифы по должности и
  гарантированные часы*).

**Формула и плановые начисления (S3)** — для настраивающего:
- *Виды расчёта*: новый способ **«Формула»** (выражение, переменные, «Проверить на сотруднике») и колонка «Из чего
  считается» у всех видов — см. *Виды расчёта: формула и база*. При обновлении существующие виды **по ступеням стажа**
  становятся «для всех сотрудников» (так они и считались); остальные остаются «только со строкой», как раньше.
- *Должности (CORM)*: **типовые начисления** каждой должности (кнопка с кошельком) — заполняют таблицу «Начисления и
  удержания» в приказе о приёме.
- Нумерация документа «Изменение плановых начислений» — серия **MA** (*Администрирование → Настройки → Нумерация*); его
  печатная форма — в *Печатных формах*.
- Порядок расчёта исправлен по сути: доплата до минимальной зарплаты и ручные исправления делаются **до** видов, которые от
  них зависят (профсоюз и алименты теперь берутся и с MINIM, и с вручную исправленного оклада).


**Налоговый режим (S4)** — вверху страницы *Константы зарплаты*: общий режим / **резидент IT-парка** с «действует с»
(месяц после даты статуса, НК ст. 375) и историей. Новые константы: `it_park_tax_pct` 7 %, `it_park_min_pct` 30 %,
`it_park_insured_pct` 68 %, `it_park_sick_covered` (дни болезни за счёт работодателя покрыты единым налогом — проверить),
`it_park_count_maternity` (отпуск по беременности в минимуме на работников — проверить), `it_park_sales_alert_day` 20.
Новые печатные формы: «Единый налог IT-парка — расчёт месяца (IU17)», «ISAPTI17», «Годовая справка работнику (IT-парк)».
См. [Режим IT-парка](help:payroll/it-park).
